# wgpu-ocaml — design contract and implementation status

> **This document, and every file it governs, was written by AI agents.**
> See the README's *Authorship* section.

This is the contract between the generator (`gen/`), the vendored headers
(`vendor/`), the hand-written runtime (`lib/wgpu_loader.ml`,
`lib/wgpu_callback.ml`), the separate `wgpu.utils` library (`utils/`), the
tests and the examples.
**If you change an interface described here, update this file in the same
change.**

Status summary at the end (§10) — start there if you are picking the project
up.

## 1. Goals and non-goals

Goals:

* Bind the whole of the WebGPU C API (`webgpu.h`) **and** the wgpu-native
  extensions (`wgpu.h`) for one pinned wgpu-native release, faithfully:
  same names, same values, same struct layouts, same defaults.
* Generate that surface from the **vendored headers** with a deterministic
  OCaml generator; commit the output so users need only `ctypes` and
  `ctypes-foreign`.
* Load `libwgpu_native` dynamically at run time (`Dl.dlopen`). No C stubs,
  no headers at build time, no linker flags.
* Prove the binding against the real ABI (a C probe compiled from the
  vendored headers) and against a real GPU (lavapipe).
* Ship, **as a separate library**, only the handful of helpers that nearly
  every program has to write anyway and that the other wgpu-native bindings
  (WebGPU-C++, `wgpu_native_zig`, `wgpu-odin`, Silk.NET) also ship (§4).

Non-goals (deliberately, to keep this a simpler sibling of `ocaml-vulkan`):

* **No ergonomic layer.** The `wgpu` library is raw bindings only: no
  descriptor builders, no exception-based error handling, no arena, no
  logging wrapper, no `with_*` scoping helpers. `Wgpu.Callback` is not an
  exception to this rule — it is the only *correct* way to build the function
  pointer a WebGPU descriptor wants (§5).
* No windowing, surface or swapchain helpers (the raw surface entry points are
  all bound).
* No async/effects/Lwt integration. WebGPU's async calls are driven by
  polling, which is what wgpu-native itself does (§5).
* No attempt to support several wgpu-native versions at once. One pin,
  one generated surface, a runtime version gate.

## 3. The bindings (generated)

### 3.1 Naming

| C | OCaml |
|---|---|
| `WGPUBufferDescriptor` (struct) | `Wgpu.Types.BufferDescriptor` |
| `WGPUBuffer` (handle) | `Wgpu.Types.Buffer` |
| `WGPULoadOp` (enum) | `Wgpu.Types.LoadOp` |
| `WGPUBufferUsage` (bit set) | `Wgpu.Types.BufferUsage` |
| `WGPUBufferMapCallback` (fn ptr) | `Wgpu.Types.BufferMapCallback` |
| `WGPULoadOp_Clear` | `Wgpu.Types.LoadOp.clear` |
| `WGPUTextureFormat_RGBA8Unorm` | `Wgpu.Types.TextureFormat.rgba8_unorm` |
| `WGPUTextureDimension_2D` | `Wgpu.Types.TextureDimension.v2_d` |
| struct field `nextInChain` | `Wgpu.Types.BufferDescriptor.nextInChain` |
| `wgpuDeviceCreateBuffer` | `Wgpu.Fn.wgpuDeviceCreateBuffer` |
| `WGPU_STRLEN` | `Wgpu.Types.Constants.strlen` |

Rules, enforced by the generator (it aborts on a collision):

* Type names lose the `WGPU` prefix and keep their CamelCase.
* **Struct field names and entry-point names keep their exact C spelling**, so
  the headers stay greppable from OCaml. OCaml keywords get a trailing `_`
  (`WGPUComputeState.module` → `ComputeState.module_`).
* Enum/bit-set constants are `snake_case` of the part after the `_`, with a
  leading `v` when that would start with a digit (`_2D` → `v2_d`). Acronym
  runs break correctly (`RGBA8Unorm` → `rgba8_unorm`).
* Every generated module exposes `c_name`, and enums/bit sets expose
  `values : (string * t) list` and `to_string`, so the C spelling is always
  recoverable at run time.

### 3.2 Representation

| C | ctypes | OCaml value |
|---|---|---|
| enum (`WGPUXxx`) | `view` over `uint32_t` | `int` |
| bit set (`WGPUFlags` typedef) | `view` over `uint64_t` | `int` |
| `WGPUBool` | `uint32_t` | `Unsigned.UInt32.t` |
| handle (`WGPUFooImpl *`) | `ptr` to an incomplete struct | `Foo.t` |
| struct | `Ctypes.structure` | `Foo.t` |
| function pointer typedef | `Ctypes.static_funptr` | `Foo.t` |
| `WGPUStringView` | struct `{ char const *; size_t }` | `StringView.t` |

Enums and bit sets are plain `int` on purpose: they are compared, or-ed and
printed constantly, and every value in these headers fits (the generator
rejects a bit set constant that would not fit in an OCaml `int`).

Bit sets provide `combine : t list -> t`, `( + )`, `mem ~bit`, `to_string`.

### 3.3 Struct defaults — `init ()`

Every struct module has `init : unit -> t`. It returns **fully zeroed** memory
with the defaults of the header's `WGPU_*_INIT` macro applied. Zero is *not* a
valid default for WebGPU: `WGPULimits` is all-`WGPU_LIMIT_U32_UNDEFINED`,
`WGPURenderPassDepthStencilAttachment.depthClearValue` is `NaN`,
`WGPUShaderSourceWGSL.chain.sType` is `WGPUSType_ShaderSourceWGSL`, and so on.
**Always start from `init ()`**, never from `Ctypes.make`.

The macros are parsed from the header, including nested and inline struct
initialisers, and every value is checked against the C compiler's view of the
same macro by `test/abi` (§7.2).

### 3.4 Entry points

`Wgpu.Fn.<exact C name>`, curried, with the literal C signature. Symbols are
resolved lazily on the first call (`lazy` + `Wgpu_loader.foreign`), so merely
referring to the module does not dlopen anything — which is what lets the unit
tests link against the library with no `libwgpu_native` present.

`Wgpu.Fn.names` lists every bound entry point in header order.

## 4. `wgpu.utils` (`utils/wgpu_utils.ml`, module `Wgpu_utils`)

A **separate dune library** — a program that does not want it never links it —
under a single admission rule:

> a helper belongs in `wgpu.utils` only if nearly every program has to write it
> anyway **and** the other wgpu-native bindings ship it too.

That rule admits exactly three things, and the file is capped at ~200 lines to
keep it that way:

| | why it qualifies |
|---|---|
| `Sync.request_adapter`, `Sync.request_device` | nothing can be done before them, and the handle only comes back through a C callback plus a `userdata` pointer |
| `Buffer.map_read_sync`, `Buffer.read_bytes` | the one genuinely asynchronous operation of every headless program; it only settles from `wgpuDevicePoll`, and the failure path is subtle (§5.3) |
| `String_view.to_string`, `String_view.of_string` | every program reads a `WGPUStringView` and writes one |

Rules:

* **Results, not exceptions.** Every fallible function returns
  `('a, status * string) result`.
* **No new types.** The arguments and results are the raw handle types, so
  everything mixes freely with `Wgpu.Fn`.
* **The caller still owns memory.** `String_view.of_string` returns the view
  *and* the value that owns the bytes it points at; keeping that second
  component alive across the foreign call is documented as the caller's job.
* **Explicit lifetimes everywhere.** No finalisers are installed anywhere in
  this project: a GPU handle released by the OCaml GC at an unpredictable
  moment is worse than a leak, and WebGPU's reference counting is already
  explicit.

What is deliberately *not* here: descriptor builders, an error sink or any
exception type, error scopes, a logging wrapper, an arena, `with_*` scoping
helpers, adapter enumeration. Those are all a few lines of `Wgpu.Fn` +
`Wgpu.Types` at the call site, and `examples/` shows them written out.

## 5. Callbacks, threads and the GC

This is the load-bearing design decision, so the reasoning is recorded here.

* `webgpu.h` passes callbacks inside structs **by value**
  (`WGPUBufferMapCallbackInfo`), passes `WGPUStringView` **by value** to the
  callback, and returns `WGPUFuture` **by value**. libffi handles all three,
  and ctypes 0.24 exposes them; this was verified against the real library
  before choosing the FFI (and is exercised by every GPU test). **No C bridge
  code is needed anywhere in this project** — there is not one line of C in
  `lib/`, only the generated ABI probe in `test/abi/` and the three test
  fixtures in `test/loader/` and `test/thread/`, none of which is part of the
  library.
* ctypes frees the libffi closure behind a `Foreign.funptr` when the *OCaml*
  value owning it is collected. A raw `static_funptr` written into a C struct
  does not keep it alive. Therefore the generated layer uses
  `Ctypes.static_funptr` (a plain pointer, no lifetime magic) and
  `Wgpu_callback` provides the only two safe ways to obtain one:
  * `Wgpu_callback.permanent` — retains the closure for the life of the
    process. Used for trampolines installed once: the uncaptured-error handler
    an application installs, and the three in `wgpu.utils`.
  * `Wgpu_callback.Userdata` — a token table addressed by the `void *userdata1`
    WebGPU hands back, so a *single* permanent trampoline can serve unbounded
    per-call closures. Tokens are released after the callback has fired;
    `Userdata.live_count ()` is asserted to return to 0 in the tests.

### 5.1 Threading — callbacks may arrive on any thread

The earlier version of these bindings assumed every callback runs on the
thread that called into wgpu, and bound everything with
`~release_runtime_lock:false`. That assumption is **not** supported by the
sources:

* `vendor/wgpu-native/include/webgpu/webgpu.h` says of the uncaptured-error
  callback that it "may be called at any time (like
  `WGPUCallbackMode_AllowSpontaneous`) ... from any thread", and that calling
  back into the API from it is unsafe;
* `wgpuSetLogCallback` installs a **process-global Rust `log` sink**
  (upstream `src/logging.rs`): any thread inside wgpu, wgpu-hal or naga that
  emits a record calls it. Grepping wgpu-native's own `src/` for
  `thread::spawn` proves nothing about its transitive backend crates.

So the bindings support foreign threads instead of assuming they do not exist:

* every entry point is bound with **`~release_runtime_lock:true`**
  (`Wgpu_loader.foreign`). Without this, a thread sitting inside a wgpu call
  would hold the OCaml domain lock and a callback arriving on another thread
  would deadlock against it;
* every closure is created with **`~runtime_lock:true ~thread_registration:true`**
  (`Wgpu_callback.permanent`), so ctypes calls `caml_c_thread_register` —
  which OCaml 5.5 documents as attaching the thread to domain 0 — and then
  acquires the domain lock for the duration of the callback. ctypes registers
  a TLS destructor so the thread is unregistered when it exits;
* ctypes refuses to release the lock for a signature that passes OCaml heap
  memory (`ocaml_string`/`ocaml_bytes`); no generated signature does, and the
  binding would raise `Ctypes.Unsupported` if one ever did. Everything passed
  to C is ctypes-managed `malloc` memory, which the GC never moves;
* all state shared between callbacks and the main thread (the retained-closure
  list, the userdata table, the recorded callback failures) is
  guarded by the single mutex in `Wgpu_callback`. `Mutex.lock` releases the
  domain lock while it waits, so a callback blocking on it cannot stop the
  main thread. One mutex, taken for short pure-OCaml critical sections only,
  cannot deadlock against itself or against the domain lock.

Dependency audit: `ctypes-foreign` already `requires = "ctypes threads"` and
its `Foreign` module initialiser both forces `Thread.self ()` and installs the
`caml_c_thread_register` hook, so the machinery above needs no runtime that was
not already linked. `lib/dune` now names `threads.posix` and `integers`
explicitly rather than relying on those transitive dependencies, and
`integers` is a declared opam dependency because `Unsigned.*` appears
throughout the public API.

This is verified, not asserted: `test/thread/` builds a C fixture that spawns
a real pthread and calls OCaml back through exactly the closures `wgpu.utils`
and the examples install — 200 plain callbacks that allocate and run
`Gc.full_major`, a
`WGPUStringView`-shaped struct passed by value, callbacks concurrent with a
busy OCaml thread and with another thread parked inside a native call, and
survival across `Gc.compact`. The GPU tests then exercise the same closures
against real wgpu-native callbacks.

Remaining limitation: the library still assumes **one OCaml domain** drives
wgpu. Registered foreign threads attach to domain 0, and nothing here is
multi-domain safe.

### 5.2 Exceptions must not cross the callback boundary

An OCaml exception escaping a libffi closure would unwind through Rust frames
holding locks — undefined behaviour. Every trampoline body therefore runs
inside `Wgpu_callback.protect ~where`, which catches everything and records it
(bounded at 64 entries). The recorded failures are **not** swallowed:
`Wgpu.Callback.take_failures` hands them to the caller and
`Wgpu.Callback.pending_failures` counts them. Since there is no ergonomic
layer to re-raise them at a checkpoint, collecting them is the application's
job; `test/gpu/test_callback_safety.ml` shows the pattern.

### 5.3 Token lifetime on failure paths

`wgpuInstanceRequestAdapter` and `wgpuAdapterRequestDevice` answer
*synchronously* in wgpu-native (its futures are stubs returning
`NULL_FUTURE`), so `Wgpu_utils.Sync` frees their userdata tokens with
`Fun.protect` on every exit path.

Buffer mapping is genuinely deferred, so the same trick would be a
use-after-free waiting to happen. When the polls run out,
`Wgpu_utils.Buffer.map_read_sync` instead **cancels** the mapping:
`wgpuBufferUnmap` on a buffer whose map is still pending makes wgpu-core
deliver the callback immediately with `MapAborted` (wgpu-core 29.0.3,
`resource.rs`, `Buffer::unmap` / `unmap_inner`), after which the token is safe
to free. If that somehow does not settle it, a bounded drain of eight polls
follows, and only then is the token **abandoned** — kept forever and counted in
`Wgpu.Callback.Userdata.abandoned_count ()` — rather than freed while native
code still holds the pointer. `test/gpu/test_callback_safety.ml` drives that
path with `~max_polls:0` and asserts that nothing leaks and the buffer is
immediately reusable.

* Running the OCaml GC *inside* a wgpu callback is tested
  (`test_gc_lifetime.ml` calls `Gc.full_major ()` from a map callback while
  wgpu-native is on the stack, then checks the mapped data).
* `WGPUFuture`/`wgpuInstanceWaitAny` are **not** functional in wgpu-native
  v29 (`wgpuBufferMapAsync` returns a null future — see upstream
  `src/lib.rs`, "TODO: Properly handle futures"). `wgpu.utils` therefore
  ignores futures and polls; the future entry points are bound but should not
  be relied on.

## 6. Loading and the version gate (`lib/wgpu_loader.ml`)

Search order (first match wins):

1. `$WGPU_NATIVE_LIB` — a full path. **Authoritative**: if it is set and does
   not load, loading fails rather than silently finding another copy.
2. `$WGPU_NATIVE_LIB_DIR` — a directory, same authoritative rule.
3. `$WGPU_OCAML_CACHE_DIR` / `$XDG_CACHE_HOME/wgpu-ocaml` /
   `~/.cache/wgpu-ocaml` → `wgpu-native-<pinned version>/lib/…`, i.e. where
   `scripts/fetch_wgpu_native.ml` installs.
4. The system search path (`libwgpu_native.so` / `.dylib`, `wgpu_native.dll`).

On success the loader calls `wgpuGetVersion` and compares it with the pinned
version (`0x1d000101` = 29.0.1.1). A mismatch raises
`Wgpu.Loader.Version_mismatch` unless `WGPU_OCAML_ALLOW_VERSION_MISMATCH=1`,
which downgrades it to a warning. Failure to find the library raises
`Wgpu.Loader.Not_found_` with a multi-line diagnostic listing every path tried,
why it failed, and the exact command that installs it.

Two details that are easy to get wrong, and are tested in `test/loader/`
against tiny C fixtures rather than a second wgpu-native build:

* a shared library that opens but does not export `wgpuGetVersion` is *not* a
  wgpu-native build. That case is reported as a candidate failure ("does not
  export wgpuGetVersion, so it is not a wgpu-native library") inside the usual
  diagnostic, instead of letting a bare `Dl.DL_error` escape;
* a handle the loader rejects — wrong version, or not wgpu-native — is
  `Dl.dlclose`d again, so a rejected library does not stay mapped with its
  initialisers live for the rest of the process. The fixtures observe this
  with a destructor that appends to a file.

## 7. Testing

Three tiers, deliberately separated so the cheap ones run anywhere.

### 7.1 `dune test` (alias `runtest`) — no GPU, no libwgpu_native

* `test/unit/test_pin.ml` — pin metadata, version encoding, and that every
  entry point wgpu-native leaves unimplemented is nevertheless bound.
* `test/unit/test_naming.ml` — the naming/representation rules of §3, the
  bit-set helpers, sentinels, and `init ()` defaults.
* `test/unit/test_coverage.ml` — rescans the headers with a *different*,
  naive scanner (`test/unit/header_scan.ml`) and requires set equality with
  the generated inventories (entry points, structs, handles, enums, INIT
  macros). This is what makes "nothing was silently dropped" a test rather
  than a claim.
* `test/unit/test_vendor_headers.ml` — SHA-256 of the vendored headers against
  `pin.txt` (plus FIPS self-test vectors for `scripts/sha256.ml`).
* `test/unit/test_loader_diagnostics.ml` — the missing-library diagnostic.
* `test/gen/` — the generator's "abort rather than guess" rules, on synthetic
  headers: a bit-set constant using bit 62 or bit 63, an enum constant that
  would shadow a member the generated module defines itself, an unknown macro
  in the `WGPU_` namespace, and (the positive case) an *indented* `#   define`
  that must still be seen.
* `test/site/` — what `doc/site/build_site.exe --out DIR` is allowed to
  delete: an output directory containing the inputs, an unrelated non-empty
  directory, a symlinked `--out`, a symlink inside an owned output, and a
  repeated successful build.
* `test/loader/` — needs a C compiler. The version gate and the
  "not a wgpu-native library" path, see §6.
* `test/thread/` — needs a C compiler. Callbacks arriving on a foreign
  thread, see §5.1.
* `test/abi/` — needs a C compiler. `gen.exe abi-probe` emits a C program
  that prints, from the **vendored headers**, every struct size/alignment,
  every field offset, every enum and bit-set value, every sentinel, and every
  `WGPU_*_INIT` field value; `dump_abi.exe` prints the same from **ctypes and
  the generated bindings**; the test is a `diff` of the two (1914 lines,
  including 543 default-value assertions).

  **What that does and does not prove.** It proves the *layout* (sizes,
  alignments, field offsets), the *values* (every enum and bit-set constant,
  every sentinel `#define`) and the *defaults* (every field of every
  `WGPU_*_INIT` macro) agree with the C compiler's view of the vendored
  headers. It does **not** prove type-level equality: a field the parser
  mis-typed as a same-width type (`float` vs `uint32_t`, a pointer vs
  `uint64_t`) has the same offset and, for the default dump, the same printed
  value on both sides, so the diff would stay clean. Nor does anything check
  *entry-point signatures*: `test/unit/test_coverage.ml` compares names only,
  and roughly 30 of the 228 entry points are actually called by `test/gpu`.
  Closing that gap would need a per-field type tag emitted by both sides
  (`_Generic` on the C side); it is a known, deliberate limitation rather than
  an oversight.

### 7.2 `dune build @gpu` — needs libwgpu_native and an adapter

Every one of these drives the raw entry points directly, with `wgpu.utils` for
the adapter/device requests and the buffer readback, and installs its own
uncaptured-error callback so that "the device reported an error" is an
assertion rather than a library feature.

`test/gpu/` (71 checks on the reference lavapipe host; `test_device` has one
check per enumerated adapter): `test_device` (loader, version, adapter info, limits,
features, the two-call enumeration protocol), `test_compute` (exact numerical
readback), `test_render` (exact pixel readback), `test_errors` (bad WGSL and an
invalid buffer usage are reported through the uncaptured-error callback and the
device stays usable), `test_gc_lifetime` (compaction between calls, descriptor
churn under `Gc.full_major`, and a full major collection *inside* a wgpu
callback), `test_callback_safety` (an exception raised inside a real wgpu
callback is recorded by `Wgpu.Callback.protect` instead of unwinding into Rust;
a mapping that does not complete is cancelled with no leaked or abandoned token
and leaves the buffer usable; a mapping wgpu *rejects* reports its status
through the map callback and its validation error through the uncaptured-error
callback, and leaks nothing).

Force the software rasteriser with
`VK_ICD_FILENAMES=/usr/share/vulkan/icd.d/lvp_icd.json`.

### 7.3 `dune build @gen` — determinism

Regenerates all four generated modules from the vendored headers and `diff`s
them against the committed copies; `dune promote` accepts a new output. CI
should run this to prove the committed generated code matches the generator.

## 8. Regenerating

```
dune build @gen          # fails if the committed output is stale
dune promote             # accept the regenerated files
```

or by hand:

```
dune exec gen/gen.exe -- types vendor/wgpu-native/pin.txt \
  vendor/wgpu-native/include/webgpu/webgpu.h \
  vendor/wgpu-native/include/webgpu/wgpu.h > lib/generated/wgpu_types.ml
```

(`types`, `fn`, `abi`, `pin`, `abi-probe`, `summary`.)

Bumping wgpu-native means: replace the two headers, update every field of
`vendor/wgpu-native/pin.txt` (including the `unimplemented` list, extracted
from upstream `src/unimplemented.rs`), `dune build @gen`, `dune promote`,
`dune test`, `dune build @gpu`. The generator **aborts** on any construct it
does not understand, so a header that grew a new C feature fails loudly at
generation time instead of producing a wrong binding.

## 9. What is covered and what is not

Generated (complete for the pinned headers, verified by
`test/unit/test_coverage.ml`):

| | count |
|---|---:|
| entry points (`Wgpu.Fn`) | 228 |
| structs (incl. 1 anonymous union) | 114 |
| enums | 70 |
| bit sets | 8 |
| enum/bit-set constants | 643 |
| opaque handles | 23 |
| function-pointer typedefs (11 callbacks + `WGPUProc*`) | 214 |
| `WGPU_*_INIT` default sets | 92 |
| sentinel `#define`s | 13 |
| generated OCaml | ~15,500 lines |

There is no second list of "what the wrapper covers": every entry point of the
pinned headers is bound, and `wgpu.utils` wraps none of them (§4).

Not usable at all in wgpu-native v29 (documented upstream limits, not binding
gaps): `WGPUFuture`/`wgpuInstanceWaitAny` (§5), `wgpuGetProcAddress`, and the
35 entry points listed as `unimplemented` in `pin.txt`, which **abort the
process** when called (they are bound so callers can see them; `test_pin`
keeps the list honest).

Inherited from upstream, and documented rather than papered over:
`wgpuInstanceEnumerateAdapters` has a two-call protocol with no capacity
argument, which `test/gpu/test_device.ml` exercises as a caller would. The
filling call writes as many entries as the driver reports *at that moment*
(`std::slice::from_raw_parts_mut(adapters, count)` in upstream `src/lib.rs`),
and each call re-enumerates: wgpu-core 29.0.3 `Instance::enumerate_adapters`
walks the fixed `instance_per_backend` list and calls
`hal::Instance::enumerate_adapters` afresh, while the sizing call drops the ids
it created. Nothing is cached, so the count is only stable while the set of
physical adapters is. Clamping the second count on the OCaml side would *not*
be a fix — the native write happens before the count is returned — so the
caller has to live with the precondition instead — which is one reason
enumeration is not in `wgpu.utils`. The set of *backends* cannot change: it is
fixed when the instance is created.

Platforms: developed and tested on Linux x86_64 against lavapipe. The pin
carries checksums for linux-aarch64, macos-x86_64, macos-aarch64 and
windows-x86_64, and the loader knows the right file names, but **none of the
other platforms has been executed**. 64-bit only (the bit-set-to-`int`
representation assumes it).

Known gaps, in the order they should probably be closed:

1. The ABI check does not prove type-level equality or entry-point signatures
   (§7.1). Closing it needs a per-field type tag emitted from both sides.
2. Non-Linux platforms are unexecuted (§9); CI runs Linux x86_64 only.
3. Multi-domain use is unsupported: foreign callback threads register with
   domain 0 (§5.1).
4. `wgpuInstanceEnumerateAdapters` has an upstream two-call protocol whose
   soundness depends on the adapter set being stable (§9).
5. **Licensing is deliberately unset.** `dune-project` has no `license:`
   field, so `wgpu.opam` has none either (`opam lint` reports exactly that one
   warning), and there is no `LICENSE` file for the original code: the owner
   has not chosen one. The vendored third-party material keeps its own
   licences (`vendor/wgpu-native/licenses/`, `PROVENANCE.md`) and those must be
   preserved whatever is chosen. Do not copy a licence from the sibling
   project by default.
